# Process

## Active tree

`Lin/v001` is the only active tree. `Win/` and `Mac/` will sit beside `Lin/` when they start. Each
`<OS>/<version>` is a self-contained world, and there is no shared source directory.

## Build order

Both compilers must build and pass. Build one compiler at a time; `-j` within a build is fine.

1. `gcc-debug`
2. `clang-debug`
3. `gcc-asan`
4. `gcc-release`
5. `clang-release`
6. `gcc-warn`, which is build only
7. `clang-fuzz`, which builds the fuzz harnesses and runs only a tiny smoke of each under CTest

A warning or a sanitizer report is a failure. Fix the cause and do not suppress it.

## Warnings

Every warning is an error. `docs/SECURITY.md` has the list: `-Weverything` on clang++ with its stated
exclusions, and a long explicit list on g++. The compile-fail tests prove that the flags are live on
both compilers.

- **New warnings are errors.** When a compiler update adds one, fix the code.
- **Nothing gets silenced without the owner's approval:** no pragma, attribute, per-file flag,
  `-Wno-error`, or cast added only to quiet a warning.
- Each clang exclusion has a one-line reason in `CMakeLists.txt`. Adding one needs the owner's approval.
- `gcc-warn` builds at `-O2` without `-fno-strict-aliasing`, `-fno-strict-overflow` and
  `-fno-delete-null-pointer-checks`, because those flags stop warnings firing. Its result is never shipped.
- Our own code has no exemptions, including tests, the demo and helpers. The only exempt code is the C
  glue generated by `wayland-scanner`, and system headers, which stay `SYSTEM` includes.

## Clean-room rule

jCppGUI takes concepts from U++ and no code. Do not open, read, search or copy from any U++ source,
and do not reuse U++ class names. The concepts carried over are a plain tree in which parents
contain children, clear ownership, and few dependencies with fast build cycles.

## Rules that a test enforces

Three layers look for the banned things, and none of them is complete on its own.

- **Text.** `tests/check_source_rules.sh` runs under CTest, or by hand as `bash tests/check_source_rules.sh`. It
  removes comments and strings first and also looks with lines joined. It scans every file under `include`, `src`,
  `tests` and `demo`, refuses any file type it would not scan as source, and fails outside a git checkout. It fails on
  banned type-erasure tokens, `void*` however it is qualified, aliases of `void` and of `std`, macros with a body,
  memory mapping, all byte I/O and raw byte copies outside their named helpers, stream file classes, raw memory,
  C-style casts, absolute paths, shebangs, and display or font library headers above their layer. **Text matching cannot
  be complete.** `tests/check_rules_selftest.sh` injects each known bypass and proves it is caught, which shows only
  that those bypasses are caught.
- **AST.** `tests/ast_rules.query`, run by `tests/check_ast_rules.sh` with `clang-query` over the compiler's own view of
  the code, so an alias, a macro or a split token does not hide anything from it. It runs on the clang presets only,
  because it needs a clang `compile_commands.json`, and it is skipped with a message if `clang-query` is not installed.
- **The compiler.** The compile-fail tests prove it rejects the mistakes it is meant to catch.

None of this replaces reading the code: see `docs/Review_Checklist.md`.

**Paths.** Every location derives from one base directory, the script's own directory or the CMake
source directory, plus relative paths. No absolute path is allowed anywhere in the repository, with
no exceptions and no allowlist. Scripts have no shebang and run as `bash <script>`. CMake finds bash
with `find_program`.
The compile-fail tests prove the compiler rejects the mistakes it is meant to catch.

Remove anything superseded in the same change. Leave no commented-out code or stubs.
